# Python SDK v0.28.0 — Structure & Patterns Analysis

## Overview

Python SDK contains **42+ resources** following consistent patterns. All resources inherit from `starkcore.utils.resource.Resource` and expose module-level functions.

---

## 1. Standard Resource Pattern

### Class Definition
```python
class Transaction(Resource):
    """Class docstring with detailed documentation"""
    
    def __init__(self, param1, param2, ..., id=None, created=None):
        Resource.__init__(self, id=id)
        self.param1 = param1
        self.param2 = param2
        # ... setters with type checking
```

### Module-Level Functions
Every resource exposes these operations:
- `create(objects, user=None)` — Create new resources
- `get(id, user=None)` — Retrieve single resource by ID
- `query(limit=None, after=None, ...)` — List resources with pagination
- `update(id, ...)` — Update (optional, not all resources)
- `delete(id)` — Delete (optional, not all resources)

### Example: Transaction
```python
import starkbank

# Create
transactions = starkbank.transaction.create([
    starkbank.Transaction(
        amount=1000,
        description="Transfer",
        external_id="ext-123",
        receiver_id="5656565656565656"
    )
])

# Query
transactions = starkbank.transaction.query(limit=10, after="cursor-id")

# Get
transaction = starkbank.transaction.get(id="7656565656565656")
```

## 2. Parameter Types

### Required Parameters
- **string**: ID, name, description, tax_id, email
- **integer**: amount (in cents), limit, count
- **datetime**: due_date, created_at, updated_at
- **date**: for scheduled operations

### Optional Parameters
- **list**: tags, descriptions, splits
- **dict**: metadata, rules
- **timedelta**: expiration interval

### Return-Only Attributes
- `id` — Generated by API
- `created` / `updated` — Timestamps
- `status` — Computed state (pending, processing, completed)
- `fee` — Charged by operation
- `balance` — Account state after operation

## 4. Nested Resources

Some resources contain sub-resources:

```python
class Invoice(Resource):
    # Main resource
    amount: int
    tax_id: str
    
    # Nested sub-resources
    rules: list[Invoice.Rule]
    splits: list[Split]
    
class Invoice.Rule:
    key: str
    value: any
```

## 5. Error Handling

```python
from starkbank.error import StarkError, StarkBankException

try:
    transaction = starkbank.transaction.get(id="invalid")
except StarkBankException as e:
    print(f"Error {e.error_code}: {e.error_message}")
except StarkError as e:
    print(f"Starkbank error: {e}")
```

## Key Observations for Spec Mapping

1. **All resources follow CRUD pattern**: create, get, query (+ optional update, delete)
2. **IDs are UUIDs**: 16-character numeric strings
3. **Amounts in cents**: API uses cents, not currency units
4. **Timestamps are ISO 8601**: UTC datetime objects
5. **Pagination uses cursor**: `after` parameter, not offset-based
6. **Tags for filtering**: Lightweight metadata across all resources
7. **Idempotency**: external_id prevents duplicate processing
8. **Errors are well-typed**: StarkBankException with code + message
